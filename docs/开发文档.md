# DockStats 开发文档

> 在 macOS Dock 图标上实时显示 CPU / GPU / 内存占用率的小工具。
> 最后更新：2026-10-14

---

## 1. 项目定位

用户愿望：**一个常驻 Dock 栏的图标，以实时动画显示 CPU、GPU、内存占用率**。

技术前提（已核实）：macOS 的 **Dock 图标不能承载文字流**，它是应用图标位图，只能整张替换。
因此「实时数字」有两条路：

1. 菜单栏 status item —— 可以放文字，但不在 Dock；
2. Dock 图标动态重绘 —— 每次把当前读数画成一张新位图，`NSApplication.applicationIconImage` 换上。

本项目**两条都做**：主视觉在 Dock 图标（大号数字，远看可读），菜单栏给一份紧凑冗余读数。

---

## 2. 技术选型

| 决策 | 选择 | 理由 |
|---|---|---|
| 语言 | Swift + AppKit | 系统原生，零第三方依赖，产物 160 KB |
| 构建 | `swiftc` 直接编 `main.swift` 成 .app bundle | 不用 Xcode 工程；`build.sh` 一条命令出包 |
| 采样 | Mach / IOKit 公开接口 | 无 root、无私有 API、不上架 App Store 也无需签名特权 |
| GPU 数据源 | `ioreg -c IOAccelerator` 子进程 | macOS 无公开 GPU 占用率 API；`powermetrics` 要 root（同类项目 MacSlowCooker 为此装 root LaunchDaemon，本项目不采用） |
| 常驻 | LaunchAgent（`RunAtLoad` + `KeepAlive`） | 登录自启 + 崩溃自拉起；`aqua` 会话内运行才有 Dock 图标 |

参考过的现成方案（均为确认路线可行，未抄代码）：
- `exelban/stats` —— macOS 菜单栏监控的事实标准，架构参考；
- `hakaru/MacSlowCooker` —— 用 Dock 图标显示 GPU/温度，印证 Dock 图标动态渲染可行；
- MacVitals —— 印证 GPU 占用率走 IOKit `IOAccelerator` 是通行做法。

## 3. 架构

单文件 `src/main.swift`，分五层：

```
采样层    CPUSampler / MemorySampler / GPUSampler     ← 各自独立，可单独替换
模型      Sample { cpu, gpu?, memPct, memUsedGB, memTotalGB }
渲染层    makeDockIcon(s) → NSImage(256×256)          ← 纯函数，给定数值出图
展示层    StatusItemController（菜单栏） / DetailWindowController（详情窗口）
驱动      AppDelegate：1s 采样 Timer + 0.5s 插值 Timer
```

关键设计：**采样与渲染解耦**。`makeDockIcon` 是纯函数，因此 `--dump --mock=...` 可以脱离
GUI 直接验收任意数值的成图（无屏幕录制权限也能验像素）。

## 4. 数据口径（重要，别记错）

| 指标 | API | 算法 | 已知偏差 |
|---|---|---|---|
| CPU | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` | 全核 Σ(user+system+nice) / Σ(user+system+nice+idle) 的**两次采样增量比** | 首拍无基准 → 返回 nil；需两次采样 |
| GPU | `ioreg -r -d 1 -c IOAccelerator -w 0` → `"Device Utilization %"` | 直接取该键整数 | 取**第一个**匹配的 IOAccelerator 实例；多 GPU 机器只会报一个。空闲时该键存在且为 0（≠读不到） |
| 内存 | `host_statistics64(HOST_VM_INFO64)` | (active + wire + compressor) × pageSize ÷ hw.memsize | 与「活动监视器」已用内存近似对齐；inactive / speculative / free 视为可回收，**不计入已用** ⇒ 本工具数值通常**低于**「内存压力」视角的占用感 |

页面大小走 `host_page_size()` 实取（本机 16384），不写死 4096。

## 5. 渲染规格

- 画布 **256×256**（Dock 图标最大显示 128 pt，Retina @2x 正好 256 px；再大纯属浪费合成时间）。
- 外底板：圆角 54、白 11% 描边。
- 内容区：`margin=32`、`gap=12`，三格「上二下一」：
  - 上排两块 88×88（CPU 左 / GPU 右）；
  - 下排 188×88 通栏（MEM）。
- 每格：淡色底 + 左上 13 px 标签 + **居中大号数字** + 底部 6 px 进度条。
- 数字字号**按可用宽度自适应**：先按 `maxFontSize`（上排 50 / 下排 64）排，「100」超宽则按比例缩，保证三位数不溢出。
- 配色：`< 50%` 绿 `(0.30,0.80,0.42)` · `50–80%` 黄 `(0.98,0.75,0.20)` · `≥ 80%` 红 `(0.95,0.32,0.28)`。
- GPU 读不到时显示 `—` + 灰色。

## 6. 性能与降本过程（实测）

| 版本 | 改动 | 自身 CPU | RSS |
|---|---|---|---|
| v0 | 512px 图标，4 Hz 重绘，无阈值 | **11.4%** | 105 MB |
| v1 | 256px 图标 + 2 Hz 重绘 | 5.4% | 88 MB |
| v2 | 再叠加「整数百分比变化才重绘」+ GPU 采样 1.5→2 s | **1.8%**（40 s 实测：0.73 s CPU / 40 s） | 87 MB |

结论：这类工具的 CPU 成本几乎全在**不必要的重绘**。显示的是整数百分比，小数位抖动重绘纯属浪费——这一条把开销砍掉 6 倍。

`ioreg` 子进程实测单次仅 **10 ms**，按 2 s 一次计约 0.5%，不是瓶颈（因此保留子进程方案，不引入 IOKit C 绑定复杂度）。

## 7. 验收记录（全部实测）

**数值真实性**（压力对照，同一工具采样）：

| 场景 | CPU | GPU | MEM |
|---|---|---|---|
| 空载 | 8.8% | 0.0% | 22.0% |
| GPU 压力 + 30 路 `yes` | 96.1% | 83.0% | 22.3% |
| 仅留 GPU 压力 | 10.3% | 91.0% | 22.2% |
| 全停 | 7.6% | 0.0% | 21.9% |
| +26 GB 内存压占 | — | 80.0% | 38.7% |

三项读数均随真实负载同向变化 ⇒ 采样链路可信。

**成图验收**（`--dump` 导出 PNG → 视觉核对）：
- 空载态 `CPU 14% / GPU 0% / MEM 22%`：布局对齐、无裁切；
- 高负载态 `96% / 80% / 39%`：CPU、GPU 转红，MEM 保持绿；
- 边界态 `100/100/100`（`--mock`）：三位数完整在格内、进度条填满、不压边框。

**常驻与自愈**：
- `System Events` 的 `background only is false` 列表中出现 DockStats ⇒ 系统认其为前台应用，Dock 有图标；
- `kill -9` 后 4 秒内自动重启（`runs = 2`），LaunchAgent 生效；
- 运行 40 s 后 `~/Library/Logs/DockStats.err.log` 为空。

## 8. 踩过的坑

1. **`lsappinfo info -only ... -app DockStats` 会返回 `[NULL]` + `!cgsConnection`，这是误读。**
   该查询方式匹配不上时字段全 NULL，`!cgsConnection` 只是「未取到连接状态」的标记，不等于进程真的没连 WindowServer。
   可靠的判据是 `osascript -e 'tell System Events to get name of every process whose background only is false'`。
2. **`screencapture` 在本 agent 会话内不可用**（TCC 屏幕录制权限）。
   因此验收不走截图，改用 `--dump` 导出图标 PNG——这条反而是更硬的证据（像素来自绘制代码本身）。
3. **`swiftc` 里 `makeLibrary(source:options:)` 的 `options` 不能传 `[]`**，要 `MTLCompileOptions()`（写 GPU 压力程序时踩到）。
4. **LaunchAgent 里必须 `LimitLoadToSessionType = Aqua`**，否则进程起在非图形会话，Dock 图标不出现。
5. **`NSImage(size:flipped:drawingHandler:)` 是延迟绘制**：只有真正光栅化（如 `tiffRepresentation` 或交给 WindowServer）时才执行，所以不要在 handler 里读不断变化的全局值，一律用参数传入的快照。

## 9. 运维

```bash
./install.sh                 # 编译 + 装 + 注册 LaunchAgent
./uninstall.sh               # 卸载

launchctl print gui/$(id -u)/com.tanfang.dockstats   # 看状态
tail -f ~/Library/Logs/DockStats.err.log             # 看错误
```

产物位置：`~/Applications/DockStats.app`、`~/Library/LaunchAgents/com.tanfang.dockstats.plist`。
本仓 `build/` 已 gitignore。
