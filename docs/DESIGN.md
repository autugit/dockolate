# Dockolate 界面规范（DESIGN.md）

> 这份文件是界面的**唯一权威**：token、组件、布局语法、验收口径都从这里取。
> 数值全部来自 `src/CardKit.swift` / `src/main.swift` 的实际实现（反推，不是另起一套）。
> 改界面时先改这里，再改代码；代码与文档冲突以代码为准，并回头修文档。

最后更新：2026-11-01（媒体指标：轮次 / 每轮耗时 / 当前这轮）

## 1. 设计立场

一块常驻 Dock 的**仪表**：信息密度高、状态一眼可判、不抢注意力。
→ 表面原型是「监控 + 操作」：读数用大字号 + 颜色分级；操作只出现在确实能动手的行上。

三条硬约束：

1. **数字要能被信任**：每个数字都必须有来源（实测 / 估算 / 引擎自报），拿不到就写「—」，不编。
2. **状态用颜色，颜色只用一套语义**：蓝＝低/待机，绿＝正常/可拉起，黄＝勉强，红＝危险/不足，紫＝未知。
3. **能动手的行必须有反馈**：按钮点了要有「拉起中 / 停止中 / 失败原因」的可见变化。

## 2.5 封装与接口（2026-11-03 用户裁定）

**问题**：程序要被用户的 AI 深度调用，但不能被同用户进程（含本地模型）误改坏。

- **程序本体 vs 状态**：`.app` 只含二进制 + 图标 + `adapters.json`；**所有可写状态**在
  `~/Library/Application Support/Dockolate/`（经 `SupportDir` 单一入口，`DOCKOLATE_SUPPORT_DIR` 可覆盖）。
  运行时不写自己的 bundle。
- **两级安装**：`~/Applications`＝开发版（自己可写）；`/Applications`＝发布版，
  `root:wheel` + 去写权限（`tools/install-system.command`）——发布版同用户进程改不动，升级整体替换。
- **完整性**：`build.sh` 在签名前写 `Contents/Resources/manifest.json`（资源 SHA-256，被签名封存）；
  可执行文件由代码签名负责（arm64 内核强校验：改代码段直接 `Killed: 9`）。
  `--doctor` 与启动提示都会指出「哪个文件被改过」。只报告不阻断。
- **管理 API**：`--api '<json>'`，一个请求一行 JSON 回答；覆盖模型的增删改查、拉起/停止、
  配置、工作组、自检。写 `registry.json` 走「原始 JSON → 改字段 → 原子写回」（不丢未知字段），
  写前留 `.bak`。契约见 `docs/CLI_API.md`，测试见 `tests/verify_api.sh`。
- **危险动作的护栏**：删配方不动权重；删正在跑的配方要 `stop:true`；没配 `stop` 的强杀要 `force:true`；
  拉起前做与界面同一条内存预检（`force:true` 可跳过）。

## 3. 布局语法

```
窗口 800×720（最小 720×560）
┌ 顶栏：Dockolate · C/G/M 读数 · 可用内存 ─────── [首页][AI 管理] ┐
├ 页面（NSScrollView + 垂直卡片栈，左右各 20）──────────────────┤
│  卡片：标题 +（右上：副标题 / 操作按钮）+ 内容栈（内边距 16）   │
└────────────────────────────────────────────────────────────┘
```

- **一级导航只有两个**：首页（监控）/ AI 管理（操作）。用 `NSSegmentedControl`，不做侧边栏。
- 卡片宽度一律撑满页面；内容用 `NSStackView` 垂直排列，**不手工摆 frame**。
- 需要等宽的横向分组（三个指标格、三列进程榜）用 `distribution = .fillEqually`。
- 行 = 横向 stack：左侧（点 + 名称 + 副标题）/ 弹性空隙 / 右侧定宽列（盘占、估算、状态、按钮）。
  需要「点得动」的行才放按钮；其余行不放，避免视觉噪声。

### 3.1 首页（监控）

| 卡片 | 内容 |
|---|---|
| 系统总览 | 三格：CPU / GPU / 内存（大数字 + 水位条 + 一行说明），下方一行 Z（压缩+换页）与换页量 |
| 内存去向 | 一条堆叠条（应用 + 内核联动 + 压缩 + 其余）+ 一行图例（含缓存与空闲绝对值）；GPU 显存导致应用/联动重叠时，两段合并成「应用+显存」，图例注明重叠 |
| 本机 AI 模型 | 最多 5 行（名称 · 状态徽标 · 内存），脚注给「另有 N 个」与未加载数量 |
| 进程排行 | 三列等宽：CPU / GPU / 内存，各 3 行 |

### 3.2 AI 管理（操作）

| 卡片 | 内容 |
|---|---|
| 模型运行时 | 每个在内存里的模型一行：▸ 展开 / 名称 · 引擎 / 状态徽标 / 内存；第二行指标：运行时长 · prefill · decode · 请求数 · 输入/输出 token；展开后给 TTFT、数据来源、最近请求时间与口径说明。**生图 / 视频不显示 prefill · decode**，改显示 已出几张（段） · 每轮耗时 · 当前这轮已用（见 3.4） |
| 模型管理器 | 摘要行（可用内存 / 权重数 / 可拉起数 / 扫描耗时）+ 按分类分组（对话 / 生图 / 视频 / 语音 / 嵌入 / 服务 / 部件）+ 每行：状态点 · 名称 · 来源路径 · 盘占 · 估算内存 · 三色徽标 · [拉起][卸载] |
| 工作组 | 每个工作组一行：名称 · 成员 · 合计估算 · 三色徽标 · [启动全部][停止全部][删除]；右上「＋ 新建」 |

## 3.3 AI 管理 · 卡片流与内存池（2026-10-29 用户裁定）

**目标**：把单列列表改成自适应卡片网格，让窗口可以缩到「一行一个模型」；用一根内存池条替代文字摘要。

### 内存蓄水池（2026-11-03 用户裁定 · 第四版：敞口水箱 / 池外小箱 / 块内名字）

> 用户令：**废弃冰山方案**。未进入内存的权重不再在池子里凸起，改放池子右侧下方的另一个小箱子。

- **水箱固定大小、顶部开口**（用户令）：只画左右两壁与池底（底部 r=10 圆角），口沿不封线。
  视图固有高度固定；唯一例外是「溢出」时在口沿之上多留 ≤56 pt，用来显示红色警告。
- **池内自下而上**：预留（最底，不可用）→ 压缩 → 系统内核 → 应用与其他 → 模型 → **空闲**。
- **剩余空间统一挪到最上面**（贴着口沿＝容量线那一段），统一**绿色**（`0.30/0.80/0.42`）。
- **模型按体积竖直叠放**，不并排多列：竖直方向才是 GB 轴；并排会让各列起始高度错开，
  还在高处留出一块「谁都不占」的空白，读不出余量（2026-11-03 实测后改）。
- **溢出＝红**：模型高过口沿（已用 > 物理内存）的部分画红色条，并在口沿上方给一个
  「溢出 N GB（模型名）」气泡；⛔ 名字不写在红块里——红字压红块读不出（实测踩过）。
- **未载入内存的权重＝池外小箱**（2026-11-03 用户令·第三版）：**宽窗口放在池子左侧**，
  做成**瘦高**形（96 pt 宽、与池子同高、**上下都齐**——底部不齐平是上一版被否的原因）。
  箱内每块**颜色与池内同一模型相同**，**块高按与池子同一个 GB 比例**画（可跨图比较，
  因此不再需要「高度＝占比」这类说明文字），底对齐、自下而上同序；
  名字按英文分行惯例在空格/连字符处**折成多行**，块内裁剪。
  标题两行：「池外」/「未载 N GB」；池内模型全部驻留时写「全部驻留」。
- **窄窗口（< 620 pt，实测应用最小宽 420）换单列版式**（2026-11-03 用户令）：
  池子在下先占满宽度，图例与池外小箱依次排到池子**下面**；空间不够时**优先缩小池外小箱**
  （124 → 64 pt）、箱内**不写模型名**（名字靠池内块与颜色关联）；池旁文字**大幅简化**为
  「物理 X · 已用 Y · 空闲 Z」一句 + 一行色块（空闲/内核/应用/压缩/预留，放不下就折成两行），
  ⛔ 不再列模型行与口径说明。断点切换时视图固有高度随之变化（`setFrameSize` 里
  `invalidateIntrinsicContentSize`）。
- **GUI 里不写实现口径**（用户令）：「块内名字在高度够时才写 · 溢出＝红」这类设计说明属于
  思考过程外溢，已从图例删除；界面上只留用户要看的数据与必要的色块说明。
- **长名字一律按英文分行惯例折行**（2026-11-03 用户令，通用规则，不针对某个模型）：
  池内块、池外小箱块、右侧图例的模型行都折行（空格 / 连字符处断，`hyphenationFactor = 1`），
  ⛔ 不用省略号。图例行高必须**量出来**（`legendTextHeight`），不能按固定 15 pt 估，
  否则折行后图例会压到下面的内容。
- **块内名字的高度阈值**（用户令）：`labelMinHeight = ceil(行高) + 5`（实测 17 pt）。
  色块高度 ≥ 阈值 ⇒ 块中央写名称；低于阈值不写（名字仍在右侧图例里）。
  块内文字**一律白色**（2026-11-03 用户令：这套配色配白字）；浅底（空闲绿 / 加载琥珀 / 应用蓝灰）
  上补一圈极细深色描边（`strokeWidth = -2`，黑 55%）＋轻阴影把字抬起来，字色不改。
  ⚠ 实测对比度：白字在空闲绿 ≈2.1:1、琥珀 ≈1.7:1（低于 4.5:1 的可读线），深色块 5–12:1。
- **口径与顶部内存池条同一条**（2026-11-01 裁定）：`系统 / 应用与其他 / 压缩` 三项按权重
  （wired / 应用−wired / 压缩）**分「已用 − Σ模型」的余量**，三项之和恒等于「已用 − Σ模型」。
  ⛔ 直接拿 wired 当「系统内核」会重复计数（Metal 页既在 wired 又在模型 RSS 里，
  实测（同机复现）算出 116 GB ⇒ 每张图都挂一条假溢出红条）。
- 模型驻留口径仍是**进程树 RSS**（启动器 + 引擎子进程），不用 `ri_phys_footprint`：
  footprint 不计 mmap 的权重页（125B：18 GB ↔ RSS 53.6 GB），会把最大那块错记成「应用与其他」。
- 读数自洽：预留 + 压缩 + 系统内核 + 应用与其他 + 空闲 + Σ模型 = 物理内存。
- 保留 2026-11-02 的版式纪律：池内色块一律圆角矩形（r=3）、统一 3 pt 窄缝、薄块不缩缝；
  刻度与图例画在池外。
- **本条覆盖 2026-11-02 的「池内不写任何文字」**：现在高度够就写名字（用户令）。
- 验收：`--shot-pool=<png>`（配 `--demo-pool` 正常态 / `--demo-pool=overflow` 溢出态）
  ＋ `--dump-pool` 导出与绘制同源的几何（每块 y/h/是否写名字），不靠看图估数。

### 内存池条（宽而扁的方块）

- 总长 = **物理内存**（超过它的一律不许画进池内，否则图自相矛盾）。
- **分段**：系统与其他 · 压缩 · 预留（`reserveGB`，灰色斜纹，**要画出来**）· 各模型 · 空余。
- **换页溢出接在池外**：swap 用量画成附着在池子外侧的一块（独立小段，标明「已换出 N GB」），表示「这部分被挤到另一个池里暂存」，不并入池内总量。
- 「非模型段」**必须复用 `MemoryMath.usedGB()`**（macOS 26/27 的匿名页与 wired 重复计数：常规算法一旦超过物理内存，改用 `max(应用, 联动) + 压缩`）。⛔ 不许另写口径，否则分段和会 > 总量。
- 池内模型段用**引擎自报的驻留量**（`/metrics` 的 `hardware.ram_used`，最权威）；池外卡片用 `estMemGB` 估算。两类数不混在同一根条上。
- **「凸出水面」**：模型方块从池底向上凸出池顶的部分 = `权重体积 − 当前驻留量`，意为「属于这个模型、但此刻不在内存里」（含 mmap 到 SSD 的专家层）。全部驻留时就不凸出。⛔ 凸出部分不占池内横向长度，只向上生长，避免与「占了池子多少」混淆。
- 模型段宽度统一、长度按 `L = Lmin + (Lmax − Lmin)·sqrt(mem / Mmax)`（凹函数：尺寸差异越大，长度差越小；`Lmin≈8pt` 防消失）。

### 卡片

- 最小宽 280 pt，容器宽度变化时 **1 / 2 / 3 列**自适应；最窄即「一行一个模型」。
- **2026-11-02 用户裁定（覆盖上一条的「等高」含义）**：
  - **所有方块宽度一致，只改高度**。高度编码模型大小：
    `h = 112 + (216 − 112)·sqrt(size / sizeMax)`（凹函数，与内存池段长同一条曲线）；
    `size` 取 `estMemGB`，拿不到退回 `diskGB`。
  - 高度 < 150 pt 的方块进**紧凑态**：藏副标题与状态行，只留名称 / 盘占 / 按钮。
  - **方块表面按状态着色**（不透明混色，不用低 alpha 覆盖白底）：
    蓝＝运行中/挂载待机 · 琥珀＝拉起中/停止中（边框加粗） · 绿＝可拉起 · 黄＝勉强够 ·
    红＝内存不足 · 灰＝不可单独起 / 未配置启动方式。先判「内存不足」，再判「不可拉起」，
    否则灰会把红盖掉。
  - **单一砖石网格，不按分类分段**（分段会让每段只剩一两行，一列装不下几块）。
    分类改成方块内的一个小标签；落块规则＝每块放进当前最矮的列（greedy masonry），
    排序＝在跑的置顶 → 分类顺序 → 名称（⛔ 不按大小降序，否则首屏全是最高块）。
  - 长模型名**换行显示**（两行，`wraps + truncatesLastVisibleLine` 才有末尾省略号），
    不靠把方块加宽；按钮钉在方块底部，高度变化时不会浮在半空。
  - AI 管理页面板顺序：**内存蓄水池 → 模型运行时 → 模型管理器 → 工作组**
    （2026-11-02 用户令：蓄水池放最上面；它一眼说明「内存还剩多少、谁在占」）。
- **池内卡**与**池外卡是两个组件**（信息密度与操作不同，避免状态切换时高度跳动）。
- 类型编码：**颜色 + 角标图标**（对话 / 生图 / 视频 / 服务）。⛔ 形状不用于类型——形状与大小编码互相干扰；形状只留给「部件」（lora / mmproj 做在宿主卡角上，不独立成块）。
- 池外卡带操作按钮（拉起 / 详情；后续接 `--ensure` 与切换）。

### 参数呈现（保持现状）

不区分「近期 / 长程」，沿用现有项与口径（运行时长、prefill/decode tok/s、请求数、输入/输出 tokens）。
2026-10-29 用户裁定：统计不做两档切换，也不为此新增采样缓冲。

## 3.4 媒体指标：生图 / 视频显示什么（2026-11-01 用户令）

> 用户原话：「图片和视频不应该显示预填充和解码参数，而是轮次和每轮时间、当前图片/片段的耗时。」

**判据**：配方声明了 `media`（`comfyui` / `mlxserve`）⇒ 这一行按媒体口径显示，
**不再出现 prefill · decode**（那是文本生成的两个阶段，媒体模型根本没有）。
媒体 = 一轮出**一张**图或**一段**片子；轮次按产物边界数，不按 HTTP 请求数
（ComfyUI 一个 prompt 可能出多张，H3 的 chain 一请求串多窗）。

| 位置 | 显示什么 | 文案样板 |
|---|---|---|
| 运行时行（第二行） | 运行时长 · 已出 N 张/段 · 平均 X 秒/张 · 当前第 N 张 Y 秒（视频带 `（12/20 步）`） | `运行 43 分 50 秒 · 已出 6 张 · 平均 44.4 秒/张 · 当前第 7 张 12 秒` |
| 管理器卡片（第二行） | 已跑 · N 张 · X 秒/张（观测 M 轮） · 当前 Y 秒 | `已跑 9 分 31 秒 · 2 张 · 26.3 秒/张 · 空闲` |
| 展开区（三行） | ① 当前这轮的轮次 / 已用 / 步 / 队列　② 最近一轮 · 最快最慢 · 上一条规格　③ 数据来源与口径 | `最近一轮 78.4 秒　｜　最快 74.9 / 最慢 81.2 秒　｜　上一条 124 帧 · 576×384` |

**数据来源（都不编）**：

- ComfyUI：`/queue`（正在跑哪个 prompt）+ `/history`（每条 prompt 的 `execution_start` /
  `execution_success` 毫秒时间戳）⇒ 轮次与每轮耗时是引擎真值；正在跑的那轮没有时间戳，
  按「首次在队列里看到它」起算，误差 ≤ 一个轮询周期。
- mlx-serve（H3）：引擎日志里的三条边界 —— `[minimax-h3] WxH N frames …, M steps`（开轮）、
  `step k/M`（进度）、`[video] -> Nf WxH`（出片）。日志没有时间戳 ⇒ 耗时按观测钟差算。
- 观测不到起点的那一轮（窗口打开时它已在跑 / 已跑完的历史轮次）：**计轮次、不计耗时**，
  界面写「耗时未观测（界面启动晚于这些轮次）」，平均后面标「（观测 N 轮）」。

**为什么不做**：不为了「每张图都有数」去拿引擎的阶段毫秒相加（实测会高估 ~10%，
重复计入 step 与 sampling），也不用 mlx-serve 的 Prometheus 计数器（那是 LLM 口径，
媒体请求根本不写进去）。拿不到就写「—」，见 §1 硬约束 1。

## 6. 验收

本机没有屏幕录制权限（`screencapture` 报 `could not create image from display`），
验收一律走**进程内离屏渲染**，像素来自真实视图树：

```bash
BIN=./build/Dockolate.app/Contents/MacOS/Dockolate
$BIN --shot-panel=/tmp/home.png            # 首页（真实数据）
$BIN --shot-manager=/tmp/manager.png       # AI 管理（真实数据）
$BIN --shot-manager=/tmp/demo.png --demo-models   # 注入全状态：运行 / 加载 / 待机 / 故障 + 三色
$BIN --self-test-manager                   # 分类 / 估算 / 三色 / 配方 / 指标解析（80 条断言）
$BIN --media=12345 [--watch=30]            # 媒体指标第二验收面：轮次 / 每轮耗时 / 当前这轮（每秒一跳）
$BIN --shot-manager=/tmp/x.png --shot-height=2600   # 内容比屏幕长时，直接给窗口高度
bash tests/verify_all.sh                   # 引擎探测 + 身份 + 签名表 + 管理器
```

看图时逐条过：三层色是否可分辨、按钮是否被挤压、长名称是否只有省略号而没有硬截断、
数字与说明是否同行对齐、卡片间距是否一致。**数值读数不可信**（视觉模型会把 84 读成 137），
要核对数字就读 `--dump --verbose` 的直接输出。
